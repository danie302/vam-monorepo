# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project purpose

This is a personal LLM engineering sandbox, not a product. The goal is a
personal virtual assistant (LLM chat + tools + reminders), but the repo is
used incrementally to try out LLM engineering concepts as they're learned
(prompting, tool use, memory, RAG, evals, etc.) — see `readme.md` for the
full roadmap of planned additions.

## Current status

- `vam/` — NestJS backend. Cookie-session authentication (sign up / sign in /
  sign out / me) is implemented with `@nestjs/authentication`, `@nestjs/sequelize`
  and SQLite. No LLM chat yet.
- `vam-ui/` — Next.js 16 + Material UI frontend. Sign-in / sign-up pages
  against the backend's cookie session; home page is a placeholder for the chat.

## Stack

- Frontend: React UI built on Next.js
- Backend: NestJS
- Database: SQLite via Sequelize (`sequelize-typescript` models)

## Initial scope (first milestone)

Per `readme.md`, the first version is intentionally small:

- Basic chat UI
- Send a message, get a response from an LLM
- User authentication (sign up / log in)
- No memory, tools, or other persistence yet

Everything beyond this (conversation memory, tool/function calling, RAG,
multi-step agents, etc.) is deliberately deferred — check `readme.md`'s
roadmap before adding a feature to confirm it isn't intentionally
out of scope for the current milestone.

## Working in this repo

Backend commands (run in `vam/`):

- `npm run start:dev` — dev server on `PORT` (default 3000)
- `npm run lint` — oxlint
- `npm test` — unit tests (vitest, `src/**/*.spec.ts`)
- `npx vitest run src/auth/application/sign-in.use-case.spec.ts` — a single test file
- `npm run test:e2e` — e2e tests (`test/*.e2e-spec.ts`, in-memory SQLite)

Backend architecture (clean architecture, organized by feature module):

```
src/<feature>/
  domain/          entities, repository ports (abstract classes), domain errors
  application/     use cases (plain classes) and ports for external services
  infrastructure/  adapters: sequelize/, in-memory/, nest-authentication/
  presentation/    http/: controllers, zod DTOs, response mappers, error filters
src/database/      DatabaseModule: the only place that picks the database
```

- Dependency rule: `domain/` and `application/` never import `@nestjs/*`,
  `sequelize*` or `zod`. Check with
  `grep -rnE "from '(@nestjs|sequelize|zod)" src/*/domain src/*/application`.
- Use cases are not `@Injectable()`: they are wired with `useFactory` in their
  feature module. Ports are abstract classes so they work as DI tokens.
- Repositories return domain entities, never ORM models. ORM errors are
  translated to domain errors in the adapter (e.g. `UniqueConstraintError` →
  `EmailAlreadyRegisteredError`), and presentation filters map those to HTTP.
- Changing the database: implement the ports (e.g. `UserRepository`, plus the
  `@nestjs/authentication` `SessionStore`) and bind them in a module like
  `DatabaseModule`. Every `UserRepository` must pass
  `user-repository.contract-spec.ts`.
- Ids are UUIDs generated by the domain (`User.create()`), not the database.

Backend notes:

- Auth: `AuthenticationModule` registers a global guard, so every route
  needs a session unless marked `@Public()`. Sessions are stored in SQLite
  (`src/auth/infrastructure/sequelize/sequelize-session.store.ts`).
- Validation: zod schemas passed as `@Body({ schema })`, checked by the global
  `StandardSchemaValidationPipe`.
- Relative imports use the `.ts` extension (`import { User } from './user.ts'`):
  `rewriteRelativeImportExtensions` turns them into `.js` in `dist/`.
- `useDefineForClassFields: false` in `tsconfig.json` is required by
  `sequelize-typescript`: class fields would otherwise shadow model getters.
- DB file: `DB_STORAGE` (default `.db/data.sqlite3`). Missing tables are
  created at startup by `synchronize`, which never alters existing tables:
  delete the file after changing a model (no migrations yet).
- `allowInMemoryStorage: true`: the `mfa` and `refreshTokens` auth stores are
  in memory (fine while MFA and tokens are unused). Implement them before
  enabling either feature.
- `WEB_ORIGINS` (comma separated) enables CORS with credentials and lets
  those origins use the session cookie. Unset, it defaults to the frontend
  dev server (`http://localhost:3001`), and to nothing when
  `NODE_ENV=production` (`src/config/origins.config.ts`).

Frontend commands (run in `vam-ui/`):

- `npm run dev` — dev server on port 3001 (the API trusts this origin by
  default)
- `npm run lint` — eslint; `npm test` — vitest (`src/**/*.spec.ts`)
- `NEXT_PUBLIC_API_URL` — API base URL (default `http://localhost:3000`,
  see `.env.example`)
- `NEXT_PUBLIC_AUTH_ADAPTER` — `http` (default, the API) or `memory` (accounts
  in the browser tab, lost on reload; no backend needed). Read in
  `src/container.ts`; `NEXT_PUBLIC_*` vars are inlined at build time, so
  restart `npm run dev` after changing them

Frontend architecture mirrors the backend:

```
src/<feature>/
  domain/          entities, validation rules, repository ports, errors
  application/     use cases (plain classes)
  infrastructure/  adapters: http/ (the API), in-memory/ (tests)
  presentation/    React: context providers, guards, components
  <feature>.module.ts   wires use cases to an adapter
src/shared/        ApiClient, MUI theme, brand colors, VAM logo
src/container.ts   composition root: the only place that picks adapters
src/app/           Next routes only: (auth)/ guest pages, (app)/ signed-in pages
```

- Dependency rule: `domain/` and `application/` never import `react`,
  `next` or `@mui/*`.
- The browser calls the API directly with `credentials: 'include'`; route
  protection is client-side (`RequireAuth` / `RequireGuest` in layouts).
- Material UI v9: no system props on components (`fontWeight={700}`), use `sx`.
- Brand colors live in `shared/presentation/theme/brand.ts`, not in
  `theme.ts`: that file is `'use client'`, and Server Components that import
  values from it get a client reference instead of the value.
